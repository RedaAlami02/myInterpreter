## What changed

| Finding | Fix and evidence |
| --- | --- |
| Fundamentals could commit yet return a failed publication receipt | The boundary validates each actual SQL receipt: dividend PUBLISHED counts, fundamental UPDATED identity/field/year/refreshed values, and explicit non-success for a missing company. Only verified success becomes the existing outward projection-receipt/v1. A real isolated SQL → injected REST adapter → Deno → Python test now covers both publication kinds and exact retries. |
| Fundamental publication bypassed the database guard | Both projection RPCs check the configured ceiling under the same advisory transaction lock. The default/hard maximum remains 350 MB; it can be reduced, not raised past that ceiling. Both fail-closed paths are tested. |
| Older dividend publications could overwrite newer facts | A private acceptance-head table records archive identity, the archived completion time and the normalized row hash for each logical target. Older captures and conflicting equal-time inputs are refused; exact retries retain the original head and timestamps. JSON-array identity hashing avoids delimiter ambiguity. Sequential and concurrent tests pass. |
| EXISTING valuation receipts could report a different value from saved history | SQL012 returns the persisted daily snapshot before revaluation, and reads the committed winner after a concurrent insertion conflict. Changed holdings/prices and unavailable fresh prices do not change an existing receipt or historical record. |
| ZIP manifest decompression was unbounded | Outbox import caps the container, preflights the central directory before allocating the ZIP index, limits the manifest to 64 KiB and bounds actual entry reads. The v1 packer's single-disk/non-ZIP64/no-comment format is enforced. A small compressed ZIP with a 2 MiB manifest is refused before decompression. |

Additional protections: Python publication receipts must match the submitted
projection's kind and count, with booleans rejected as integer counts. Bundle
packing uses atomic no-replace linking, preventing an output-path race from
replacing an earlier artifact. Original outbox evidence is never deleted by packing.

SQL012's staged receipt implementation and SQL013's staged publication implementation
are documented as **v2**. They have never been installed on the hosted project.
Input projection documents and the outward receipt remain v1; their fields are
unchanged. For fundamentals, the existing receipt's `records` count denotes the
validated candidate field count, not the number of fields actually changed.
Original market values, observation timestamps, raw archives, genuine ledgers,
models and previous accepted prediction contracts were not rewritten.
